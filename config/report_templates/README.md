# JSON 보고서 양식

세 양식은 테스트용 합성 예시이며 실제 은행 공식 서식이 아니다.
**양식 JSON → 항목별 값 채우기 → 보고서 JSON 저장 → 화면/PDF/DOCX 출력**으로 동작한다.
새 보고서의 원본은 `document`이고 Markdown 파일이나 Markdown 본문을 중간 저장하지 않는다.

| 파일 | 목적 |
|---|---|
| `market-daily.json` | 일일 금리·환율 상세 보고 |
| `fx-brief.json` | 기준금리 없이 환율을 짧게 전달 |
| `market-check.json` | 누락·실제 관측일 차이를 먼저 점검 |

## 회사 양식으로 바꾸기

1. 파일을 복사해 `<id>.json`을 만들거나 기존 파일을 수정한다. `id`와 파일 이름을 맞춘다.
2. `name`, `description`, `keywords`를 업무 목적에 맞게 고친다.
3. `sections`에 제목·문단·입력 항목을 원하는 순서로 배치한다.
4. `summary_instructions`에는 요약 작성 조건을 600자 이내로 적는다.
5. 변경할 때 `version`을 올린다. 같은 버전에서도 해시로 변경을 감지한다.
6. 사용 중단은 `enabled`를 `false`로 설정한다. 이미 읽은 선택으로 새 보고서 저장도 막고 과거 열람은 유지한다.
7. 검토된 회사 양식으로 교체했다면 `demo`를 `false`로 바꾼다.

예시:

```json
"sections": [
  {"type": "heading", "level": 1, "text": "일일 업무 보고서"},
  {"type": "field", "label": "기준일", "binding": "base_date"},
  {"type": "paragraph", "text": "담당자 검토 전 자료입니다."},
  {"type": "heading", "level": 2, "text": "핵심 요약"},
  {"type": "binding", "binding": "summary"},
  {"type": "binding", "binding": "fx_table"},
  {"type": "binding", "binding": "source_notes"}
]
```

`heading`은 제목, `paragraph`는 고정 문구, `field`는 이름이 붙은 단일 값,
`binding`은 요약·표·출처 목록처럼 서버가 채우는 내용이다.
고정 문구의 `**`, `#`, HTML은 서식 명령으로 해석하지 않고 글자 그대로 표시한다.

| 입력 항목 | 서버가 채우는 내용 |
|---|---|
| `base_date` | 요청 기준일 |
| `prepared_by` | 인증된 플랫폼 사용자 ID |
| `summary` | 검사한 요약 또는 제외 안내 |
| `fx_table` | 환율 표: 열 이름과 행 배열 |
| `rates` | 기준금리·실제 관측일 목록 |
| `data_quality` | 요청일·관측일·누락 여부 점검표 |
| `source_notes` | 출처·관측일·기록 재생 여부·이용 안내 목록 |
| `report_id` | 보고서 번호 |

기준일과 출처는 반드시 포함한다. `required_bindings`의 필수 자료가 없으면 저장하지 않는다.
새 데이터(심사 결과 등)를 자동으로 채우려면 해당 조회 도구와 입력 항목 연결도 필요하다.
항목 순서·제목·고정 문구는 수정할 수 있지만, 회사 원본 DOCX/HWPX의 정확한 배치 복제 기능은 아니다.

## 저장·화면·출력

저장 보고서의 `document.blocks`에는 제목·필드·문단·표·목록을 구분해 채운 값이 들어간다.
숫자 원본은 별도의 `snapshot`에 유지한다. 사용 양식의 버전·해시와 정의도 보관한다.
보고서는 플랫폼 문서 저장소(`data/documents.sqlite3`)에 저장하고, 다른 서류(만기 대출 정리표 등)와 같은 문서 형식·같은 내려받기를 쓴다.
React 화면은 이 구조화 JSON을 직접 렌더링하며 Markdown 파싱을 거치지 않는다.

- **PDF·DOCX**: 채팅 답 아래와 **내 문서** 화면의 버튼. 서버가 저장된 보고서를 번호로 찾아 변환한다
  (`GET /api/documents/{번호}/download?format=pdf|docx`, 본인 것만, 내려받은 기록을 남김).
  브라우저 인쇄 창이나 브라우저가 보낸 JSON 을 변환하는 방식은 쓰지 않는다 (저장된 적 없는 보고서를 만들 수 없게).
- PDF 는 서버의 한글 글꼴이 필요하다 (윈도우 맑은 고딕, 맥 산돌고딕 Neo, 리눅스 나눔고딕을 자동으로 찾고 `PDF_FONT_PATH` 로 지정 가능).
- JSON 원본 내려받기는 두지 않았다 (고객 정보가 든 문서도 원본째 나갈 수 있어 팀 결정 후).

`.hwp/.hwpx` 전용 내보내기는 아직 제공하지 않는다. 한글 프로그램의 DOCX 지원 여부에 따라 Word 출력 파일을 사용할 수 있으나 배치 호환은 별도 확인이 필요하다.

이전 Markdown 보고서는 변경하지 않고 화면에서 계속 읽는다. 파일 내려받기는 구조화 `document` 가 있는 보고서만 된다.
새 보고서 응답은 구조화 `document`와 채팅 문자열 필드용 일반 텍스트 `text`를 반환한다.
새 보고서의 저장·응답·화면·PDF·DOCX에 Markdown 변환은 필요하지 않다. 이전 `body_markdown` 양식만 호환 읽기를 지원한다.

## 적용·검색

파일 수정은 다음 검색·읽기부터 반영된다. 양식 수정만으로 재시작할 필요는 없다.
읽은 선택과 과거 보고서는 당시 버전으로 보관한다. 검색 후 읽기 전에 바뀌면 재검색을 안내한다.
양식 폴더는 플랫폼의 `REPORT_TEMPLATES_DIR`(기본 `config/report_templates`), 기본 양식은 `REPORT_DEFAULT_TEMPLATE`이다.

검색은 현재 로컬 키워드 방식이며 DB/벡터 RAG는 연결하지 않았다.
`keywords`에 양식명·목적·별칭을 넣는다. `priority`는 0~9, 기본 일일 양식은 1이다.
동점이면 양식을 물어보고, 결과가 없으면 임의 양식을 만들거나 저장하지 않는다.
향후 `ReportTemplateCatalog.search()`를 RAG로 바꾸면 나머지 작성·출력 계약을 유지할 수 있다.
회사·부서별 양식 권한은 해당 저장소와 연결할 때 적용한다. 지금 세 예시는 공용 테스트 양식이다.

## 실행 확인

이번 코드 변경 후 시장 MCP와 FastAPI를 재시작하고 프런트를 새로고침한다.
에이전트에는 양식 검색·전체 읽기·시장 조회·리포트 저장·리포트 읽기 다섯 도구를 선택한다.
전체 양식은 서버가 채우며 요약 모델에는 짧은 목차·작성 조건·선택한 수치만 전달한다.

```text
보고서 양식 목록을 보여줘.
2026-11-18 기준으로 일일 금리·환율 보고서 양식을 찾아 작성하고 저장해줘.
2026-11-18 기준으로 간단 환율 브리핑 양식을 찾아 작성하고 저장해줘.
2026-11-18 기준으로 금리·환율 점검 보고서 양식을 찾아 작성하고 저장해줘.
```
