# Ollama 모델 설정

채팅 모델은 `qwen3:8b-24k` 를 씁니다. `qwen3:8b` 에 컨텍스트 한도 24,576 토큰을 붙인 것입니다.

```bash
ollama pull qwen3:8b
ollama create qwen3:8b-24k -f config/ollama/qwen3-8b-24k.Modelfile
```

만들지 않아도 서버는 돌아갑니다. 그때는 `qwen3:8b` 로 대신하고, 한도가 4,096 토큰이라 긴 문서는 앞부분만 전달됩니다 (서버 로그에 경고).

## 왜 필요한가 (2026-11-23 측정, M4 16GB, Ollama 0.40)

- Ollama 는 모델에 `num_ctx` 가 없으면 메모리에 맞춰 **4,096 토큰**으로 잡습니다. 모델 자체는 40,960 까지 됩니다.
- 앱이 쓰는 OpenAI 호환 경로(`/v1`)로는 요청마다 한도를 바꿀 수 없습니다 (`options.num_ctx` 를 보내도 무시).
- 시스템 규칙과 툴 설명만으로 첫 질문이 약 2,900 토큰입니다.
- 첨부 문서는 최대 2만 자 ≈ **1만 5천 토큰**입니다 (한글 1글자 ≈ 0.73 토큰).
- 한도를 넘으면 Ollama 는 앞부분을 자르는 게 아니라 **메시지를 통째로 버립니다.** 오류도 없습니다.
  실험: 문서 2만 자를 읽힌 대화가 82 토큰(시스템 + 마지막 질문)으로 줄었고, 모델은 "보존 기간 5년"을 지어냈습니다 (정답 7년).

## 한도별 비용 (qwen3:8b)

| num_ctx | 메모리 | 짧은 질문 속도 |
|---|---|---|
| 4,096 | 5.2 GB | 18 tok/s |
| 16,384 | 6.9 GB | 20 tok/s |
| 24,576 | 7.6 GB | 20 tok/s |

한도를 늘려도 짧은 질문은 느려지지 않습니다. 느려지는 건 넣는 양입니다: 9천 토큰 문서를 읽는 데 약 55초가 걸립니다.

24,576 으로 정한 이유: 첫 질문(약 3천) + 최대 문서(약 1만 5천) + 답(최대 4천)이 들어가야 합니다. 16,384 는 모자랍니다.

## 한도를 넘을 때

앱이 보내기 전에 먼저 줄입니다 (`apps/api/src/harness/context.py`):
지난 질문의 툴 결과를 줄이고 → 오래된 대화를 빼고 → 그래도 넘치면 이번 문서를 앞부분만 보내며 잘렸다고 알립니다.
한도는 Ollama 에 물어봐서 정하고, 다른 서버를 쓰면 `LLM_CONTEXT_TOKENS` 로 정합니다.
