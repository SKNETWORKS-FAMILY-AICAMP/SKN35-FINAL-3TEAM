# 결정 사항 (2026-11-23)

팀 열린 이슈 중 이번에 정한 것과 아직 남은 것을 정리한다. "구현 상태"가 `미구현`이면 결정만 하고 코드는 아직 바꾸지 않은 것이다.

## 1. 답변 검증 (UC-01 열린 이슈)

| 항목 | 결정 |
|---|---|
| 무엇을 검사할까 | 근거 문서 이름·조항 + 숫자(기간·금액 등) |
| 검사에서 걸리면 | LLM 에게 다시 쓰게 한다. 정해 둔 횟수를 넘기면 "등록된 규정에서 근거를 찾지 못했습니다" 같은 고정 문구로 답한다 |
| 검색 결과가 0건이면 | 검색어를 바꿔 한 번만 더 찾는다. 그래도 없으면 위 고정 문구로 끝낸다 |
| 근거 형식 | 지금 형식("근거:" 한 줄 + 참고 문서 목록) 유지. 실제 내규 데이터가 들어오면 다시 본다 |
| 적용 범위 | 문서 검색 툴(`search_doc`)이 있는 에이전트 |
| 걸린 답 기록 | 기록한다. 관리자만 본다 |

구현할 때 주의할 점
- 다시 쓰기(근거가 틀림)와 다시 찾기(결과 0건)는 서로 다른 경우다. 한 질문 안에서 합친 상한을 정해 LLM 호출이 쌓이지 않게 한다 (예: 다시 쓰기 1번 + 다시 찾기 1번).
- 숫자는 출처가 두 가지다. 내규 숫자는 검색 결과와, 고객 숫자(만기일·금액)는 조회 툴 결과와 맞춰 본다. 그래서 기준은 "이번 대화의 조회 툴 결과 전체"다.
- **메일 본문도 같은 검사를 받는다.** `send_mail` 이 호출되면 승인 카드를 띄우기 전에 본문의 문서 이름·숫자를 검사하고, 틀리면 승인 카드 없이 LLM 에게 다시 쓰게 한다. 지금은 최종 채팅 답만 검사하므로 새로 만들어야 한다.
- 조항 검사는 검색 결과에 조항 정보(`heading_path`)가 있어야 한다. 지금 fixture 에는 없다.
- 걸린 답을 `audit_log` 에 남기려면 `event_type` 허용값을 늘리는 마이그레이션이 필요하다 (audit_log 는 추가만 되는 표). 답에 고객 정보가 섞일 수 있으므로 보관 기간을 함께 정한다.

구현 상태: 미구현

## 2. 승인 방식 (UC-05)

| 항목 | 결정 |
|---|---|
| 고객 안내 발송 수단 | Gmail (`send_mail`, 요청자 본인 계정) |
| 승인 | 요청자가 채팅에서 바로 승인 (A 방식). 팀장급 승인은 두지 않는다 |

- 템플릿 `uc05-maturity-notice` (만기 고객 안내 메일): `[prepare_maturity_notices, send_maturity_notice]`. 고객 한 명당 한 통, 받는 사람·참조에 다른 고객을 섞지 않는다.
- 안내문은 모델이 쓰지 않고 코드 양식(`tools/maturity_notice.py`)으로 만든다. 모델은 대출 번호만 넘긴다.
  처음 안(`send_mail` 에 본문을 직접 넘기기)은 qwen3 8b·14b 모두 메일을 보내지 않고 "보냈다"고만 답해서 바꿨다 (2026-11-23 실측).
- 흐름: 안내문 준비 → 보낼 목록을 보여 주고 "이대로 보낼까요?" → 직원이 보내라고 하면 한 통마다 승인 카드(받는 사람·제목·본문) → Gmail MCP `send_mail` 로 발송.
- 고객에게 가는 메일은 코드가 승인 카드 전에 검사한다 (`permission/customer_mail.py`): 고객 한 명당 한 통, 내 담당 고객만, `send_mail` 을 직접 쓸 때도 본문은 양식 그대로.

구현 상태: 구현 (가상 데이터 `data/fixtures/loans_demo.json`, 가짜 Gmail 로 확인). 실제 발송은 Gmail MCP 를 `GMAIL_ADAPTER=google` 로 켜고 직원 계정을 연결해야 한다. 이미 보낸 고객을 다시 보내지 않는 검사(유즈케이스 3a)는 아직 없다.

## 4. 첨부 자료와 컨텍스트

| 항목 | 결정 |
|---|---|
| 자료를 어디에 붙일까 | 지금은 대화에 붙인다. 나중에 "내 자료함"과 "에이전트 고정"(고정할 만한 문서만)을 더한다 |
| 대화가 길어지면 | 요약한다 |
| 올린 파일 보관 기간 | 1년 정도 |

구현할 때 주의할 점
- 지금은 첨부가 메시지 하나에만 붙는다. 대화에 붙이면 이후 질문에서도 같은 `file_id` 로 다시 읽을 수 있다.
- 요약은 대화 내용만 한다. 문서·툴 결과는 요약하지 않고 필요할 때 `parse_doc` 으로 다시 읽는다 (작은 모델이 요약하며 숫자를 바꾸는 사고 방지).
- `harness/context.py` 는 지금 "자르기" 방식이다. 요약으로 바꾸는 것을 작업자와 맞춘다.
- 에이전트 고정은 공유된 에이전트를 통해 고정 문서가 다른 사람에게 보일 수 있으므로 보안등급 검사가 필요하다. 고정할 문서를 누가 정하는지도 정한다.
- 1년 보관에는 자동 삭제 작업이 필요하다. 대화를 지우면 파일도 지울지, 고객 개인정보가 든 파일을 보관하는 근거를 정리한다.

구현 상태: 미구현

## 5. 거부됐을 때의 답 (하네스, dy 와)

LLM 을 쓰지 않고 코드에서 처리한다.

| 경우 | 사용자에게 보이는 답 |
|---|---|
| 권한 없음 (DENY) | 고정 문구 + 정책에서 계산한 못 채운 조건 (예: "부서장·보안등급 3 이상만 가능, 현재 등급 2") + "부서장·관리자에게 요청해 주세요" |
| 시간 초과 | 고정 문구 + "다시 요청" 버튼 |
| 승인 거절 | 고정 문구 |

- dy 의 "거부 시 LLM 없이 고정 문구" 계약과 같은 방향이라 계약 변경은 없다.
- 새로 만들 것: 못 채운 조건 계산(`config/permissions.yaml` 의 roles·conditions 기준), `harness/denial.py` 문구 반영, 화면의 "다시 요청" 버튼.
- 권한 요청 기능은 아직 없다. 생기면 안내 옆에 "권한 요청" 버튼을 붙인다.

구현 상태: 미구현
